KV-Stationary Systolic Array for MQA Inference

An attention engine that pins the Key/Value cache in array columns, streams Query vectors left-to-right, and folds softmax into the dataflow — so attention scores never touch DRAM. Hudson Strauss · Santa Clara University · HPCA

The 2D Dataflow rows = query lanes · columns = KV tokens

Each column permanently holds one token's K and V vectors. Each row belongs to one query head (MQA: all heads share the same KV). Query packets carry their running softmax state (M, L, O) and ripple right one column at a time — the diagonal wavefront below. When a packet falls off the right edge, its attention output is complete.

step 0
PE (idle slot) Q packet (M,L,O state) stationary K[t] / V[t] finished output → DRAM

The skew between rows is 1 step, and a step is effective_stagger cycles (8 at lmc=16) — not a full 135-cycle column dwell. The d-cycle dot-product latency is paid once as pipeline fill (wavefront model, SCALE-Sim validated at ≈2.5 cyc/col).

Inside a PE two pipeline stages per column

Stage 1 computes the raw attention score with lmc time-interleaved serial MACs reading taps of a stationary K shift register. Stage 2 is the Running Attention PE: two exp lookups and a d-wide vector update fold the score into the packet's running softmax state.

Area accounting caveat (§22.1): the upper vector unit at width 128 is 8× more multipliers than the 16 lower MACs, yet headline "MAC counts" include only the lower MACs. The co-sizing rule width ≥ ⌈3d/(eff_stagger − 4)⌉ shrinks it to 96 lanes at lmc=16 and just 16 lanes at lmc=4 with zero performance loss — the calculator below shows both accountings live.

Zoom into a single column's lower unit. Each of the lmc serial MACs owns every lmcᵗʰ Q packet and grinds through its full d=128-cycle dot product, reading a private tap of the stationary K register. Staggered starts mean a finished score pops out every ⌈d/lmc⌉ cycles even though every individual MAC takes 128 cycles — that interleave is the whole trick that lifts the upper softmax PE from 5.5% to 87.5% busy.

MAC-Level 2D Dataflow one head-row unrolled · cycle-accurate

The step-level simulator above says "packet p is at column c" — but at cycle granularity that's not what the silicon does. A packet's dot product takes d=128 cycles while the pipeline admits one packet per column every eff_stagger cycles, so each packet is smeared across d/eff = lmc columns at once, each column at a different stage of its accumulation, while each column's lmc MACs serve lmc different packets. The top strip shows the upper softmax PEs consuming each score the moment its MAC finishes — the (M,L,O) chain advancing one column per eff_stagger. This band is why the dwell model was wrong: at lmc=1 the band collapses to a single column (the old 135-cycles-per-column intuition); interleaving widens it.

Q Vector, Element by Element one packet · all 128 elements · cycle-accurate

The deepest zoom: a single Q packet's 128 elements (rainbow strip, q₀…q₁₂₇) feeding the columns of its band. Each cycle, column c multiplies q[t − c·eff] · k_c[t − c·eff] into its accumulator — so at any instant the same Q vector has d/eff elements active at once, one per band column, forming a comb with spacing eff_stagger that marches one element per cycle. This is the silicon reason Q is read from DRAM exactly once: the vector streams through the array and every column taps it in passing. The fill-model correction. The legacy model (A, "dwell") charged 135 cycles per column of pipeline fill. SCALE-Sim measured the real Q·K fill at 2.2–3.0 cycles/column — ruling out A by ~50× and confirming the wavefront model (B), which charges d + (R+C−1)·eff_stagger and is itself conservative.
A (dwell, ruled out) : tile = (R+C−1)·135 + (P−1)·eff B (wavefront, used) : tile = d + (R+C−1)·eff_stagger + (P−1)·eff_stagger SCALE-Sim measured : ≈ 2.5 cyc/col (B predicts 8, A predicts 135)
Consequence: at commodity bandwidth, prefill is DRAM-bound — compute sits far below the 272 MB Q+O traffic floor. lmc must be sized to bandwidth (lmc ≈ BW/128); beyond that, extra MACs are idle silicon.

Merge Extensions n levels · compute-bound regime only

Splitting the KV cache into 2ⁿ sub-arrays (each 2ⁿ× more rows, 2ⁿ× fewer columns) cuts pipeline flush from T−1 to T/2ⁿ−1 steps. Inline merge PEs combine partial (M,L,O) states in a binary tree using the same log-sum-exp math as FlashAttention's split-K reduction.

When it matters: merge extensions trade 2ⁿ× more PE rows for ~2–3× speed — worthwhile only when compute-bound (high bandwidth, low lmc). Under the wavefront model at commodity BW, n=0 and n=3 collapse onto the same DRAM floor and the extra rows buy nothing.

Silicon Re-Use: P Passes over T/P Columns latency ↔ area at a known ratio

Instead of T physical columns, build T/P and sweep the KV cache in P passes, re-injecting saved (M,L,O) state at each boundary (14 cycles, 260 B per query). Because the P=1 pipeline is already drain-dominated at large T, P passes cost only 1.02–1.11× more cycles — for a P× smaller chip. With a causal mask, finished queries are discarded at each pass boundary and their outputs streamed out early.

GQA via Row-Band Partitioning free, because K is already per-PE

Every PE already stores a private K[t] copy, so grouped-query attention costs no extra on-chip storage: split the 64 rows into G bands and let band b's columns hold K_b/V_b. Bands ripple K in parallel — vertical fill shortens from H−1 to H/G−1 steps.

KV groups G

What still costs: decode KV-residency SRAM and any KV re-streaming scale ×G, and the design still binds rows=H, MAC depth=d at design time. MLA-style latent KV breaks the stationary-KV concept itself — partitioning doesn't cover it.
